1. Resumen ejecutivo

El proyecto consiste en una API REST de gestión de gimnasio desarrollada con FastAPI y una aplicación web en React que la consume. El trabajo se organiza en cuatro fases de dificultad creciente (Esencial, Medio, Avanzado y Experto) que cubren desde el CRUD y las reglas de negocio hasta autenticación JWT, caché, WebSockets, Docker, CI/CD y despliegue en la nube.

En esta primera entrega se ha dejado preparado el andamiaje del frontend (estructura, capa de API, autenticación y enrutado por roles) y se ha generado el backlog completo en GitHub Projects, con historias de usuario, subtareas, prioridades, estimaciones y responsables.

2. Objetivo y alcance

Objetivo

Construir una plataforma que permita gestionar socios, entrenadores, planes de membresía, clases, horarios, reservas y pagos, aplicando buenas prácticas de desarrollo: separación en capas, pruebas automatizadas, integración continua y despliegue reproducible.

Alcance funcional

  • Gestión de usuarios con roles (administrador, entrenador y socio).
  • Planes de membresía y asignación de suscripciones con fechas de validez.
  • Clases, horarios y control de aforo.
  • Reservas y cancelaciones con reglas de negocio (membresía activa, aforo, solapamiento).
  • Pagos asociados a membresías.
  • Documentación interactiva (Swagger), filtros, paginación y exportación a CSV.
  • Autenticación JWT, permisos por rol, caché y disponibilidad en tiempo real.
  • Interfaz web básica para socios.

Alcance de esta entrega

  • Estructura del proyecto frontend React + Vite + TypeScript.
  • Backlog completo creado en GitHub Projects con reparto asignado.
  • Pipeline de CI con dos jobs (backend y frontend).

4.2 Capa de API

El módulo src/api/ es el único punto que habla con el backend. El cliente de axios añade el token en cada petición y, si el servidor responde 401, borra la sesión y redirige al login. Los errores se normalizan con toApiError para mostrarlos de forma uniforme.

Si el backend cambia, solo se toca esta capa; las páginas no conocen detalles de HTTP.

4.3 Autenticación y roles

  • AuthContext: guarda el usuario y su rol; expone login, logout y hasRole.
  • tokenStorage: único punto de acceso a la sesión persistida.
  • ProtectedRoute: bloquea rutas sin sesión (redirige a login) y por rol (403).

4.4 Componentes UI reutilizables

Se incluyen Button, Table, Pagination y Alert, pensados para que cada persona los reutilice en sus pantallas y mantenga una interfaz coherente.

5. Cómo encajan front y back

Generación de tipos

FastAPI publica su esquema en /openapi.json. Con npm run api:types se regenera src/types/schema.d.ts mediante openapi-typescript. Ese fichero no se edita a mano: si el backend cambia un campo, el front deja de compilar y el contrato roto se detecta en CI.

CORS

En desarrollo, Vite hace proxy de /api hacia http://localhost:8000, de modo que el navegador nunca cruza orígenes. En producción, el front llama directamente a la URL del backend y FastAPI debe permitir el origen del front en su middleware CORS.

Dónde se guarda el token

El token se guarda en localStorage y viaja como cabecera Authorization: Bearer. Al recargar, la sesión se recupera del almacenamiento.

Errores de la API

El interceptor de respuesta detecta el 401 y cierra sesión. El resto de errores se muestran con <Alert variant="error"> a partir del mensaje normalizado.

La seguridad real está en el backend

Ocultar rutas con ProtectedRoute es solo experiencia de usuario: cualquiera puede modificar el estado en el navegador. La autorización de verdad se valida en el backend en cada endpoint, comprobando el token y el rol.

7. Integración continua y despliegue

Integración continua

El flujo de GitHub Actions tiene dos jobs independientes:

  • Backend: instalación de dependencias, lint con ruff y tests con pytest.
  • Frontend: npm ci, lint, formato, tests unitarios, build (typecheck) y tests E2E con Playwright.

Contenedor y servidor web

El frontend se empaqueta con un Dockerfile multi-etapa (build con Node y servido con nginx). El nginx.conf aplica el fallback de SPA hacia index.html y cachea los assets con hash.

Despliegue

  • API y base de datos: Render o Railway.
  • Frontend: Vercel o Netlify.
  • La URL de la API se inyecta en tiempo de build con VITE_API_URL.
